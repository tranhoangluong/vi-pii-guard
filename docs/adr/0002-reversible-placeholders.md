# ADR-0002: Reversible, session-scoped placeholders

- Status: accepted
- Date: 2026-11-23

## Context

Masking with a type tag (`[PHONE]`) protects data but breaks the conversation: the LLM cannot
tell two people apart, and the user receives an answer full of tags. The answer has to come
back with the original values.

## Decision

- Default strategy `placeholder`: each distinct value becomes `[TYPE_n]`. Equal values map to
  the same placeholder within a session (`0912 345 678` and `0912345678` share `[PHONE_1]`).
  Names keep diacritics in the key, so "Lan" and "Lân" stay different people.
- The mapping lives in a `RedactionSession` stored through the `Vault` port. The default adapter
  is `InMemoryVault`: thread-safe, sliding TTL (1 hour), LRU cap, never persisted or logged.
- Session ids are 128-bit random tokens generated by the server. An unknown or expired id
  passed by a client starts a new session with a fresh id, so a client cannot attach to
  another conversation's mapping by guessing or choosing an id.
- `restore` tolerates light reformatting by the LLM (`[ PERSON_1 ]`, bare `PERSON_1`) and leaves
  unknown placeholders untouched.
- `mask` remains available for irreversible cases (logs, analytics exports).

## Consequences

- Restoring requires the same process (or a shared vault) for the whole conversation.
  A Redis adapter is the expected next step for multiple replicas.
- The vault holds raw PII in memory: TTL and `DELETE /v1/sessions/{id}` keep exposure short.
- Placeholders reveal the entity type and count to the LLM. This is intended: it keeps answers
  useful.
